Cách sản phẩm này được làmHow this product is built

Exomaly Signal

Bảng theo dõi nằm cạnh khung chat trong VS Code: việc đang chạy, lệnh nền, lượng ngữ cảnh đã dùng và các phiên làm việc khác trên máy.A monitoring pane beside the chat in VS Code: what is running, background commands, how much context has been used, and the other sessions on the machine.

Tự thiết kế cho cá nhân, không phát hành.Self-designed for personal use, not released.

1Tóm tắtSummary

  • Bảng cho biết pha hiện tại (chờ, nghĩ, viết, chạy lệnh), danh sách lệnh của lượt và của phiên, lệnh nền, lượng ngữ cảnh đã dùng và tốc độ tăng mỗi lượt, các phiên khác trên máy và thời gian chạy test.
  • Dữ liệu không rời máy: mod không gọi mạng, chỉ đọc dữ liệu có sẵn trên máy và ghi một thẻ nhỏ cho mỗi phiên để các phiên thấy nhau.
  • Chỉ quan sát: mod không đổi quyết định quyền hay kết quả của bất kỳ lệnh nào. Một file TSX do engine mod của khung chat nạp thẳng; không npm, không bundler, không thư viện ngoài.
  • The pane shows the current phase (waiting, thinking, writing, running a command), the commands of the turn and of the session, background commands, how much context has been used and how fast it grows per turn, the other sessions on the machine, and test timings.
  • Data never leaves the machine: the mod makes no network calls, only reads data already on the machine and writes one small card per session so sessions can see each other.
  • Observe only: the mod never changes a permission decision or the result of any command. One TSX file loaded directly by the chat's mod engine; no npm, no bundler, no third-party library.

3Quyết định thiết kếDesign decisions

Một file TSX, không npm, không bundlerOne TSX file, no npm, no bundler

Vì saoWhy
Engine nạp TSX trực tiếp; không có gì phải cài hay cập nhậtThe engine loads TSX directly; nothing to install or update
Phương án đã loạiRejected alternative
Nhiều module và bước build: thêm việc mà không thêm gì ở quy mô nàySeveral modules and a build step: more work with no gain at this size

Chỉ quan sát, không chạy lệnh từ modObserve only, run no commands from the mod

Vì saoWhy
Mod chạy trong chính tiến trình của khung chat; không được làm đổi hay chậm việc đang làmThe mod runs inside the chat's own process; it must not change or slow the work in progress
Phương án đã loạiRejected alternative
Chạy git từ mod để nhắc nhánh chờ push: tác giả không muốn mod chạy lệnh, và engine chỉ có cách đó ở bản dòng lệnhRunning git from the mod to flag unpushed branches: the author does not want the mod running commands, and the engine offers that only in the command-line version

Thẻ phiên trên đĩa để các phiên thấy nhauSession cards on disk so sessions see each other

Vì saoWhy
Mỗi cửa sổ có bản mod riêng; một thư mục thẻ là cách đơn giản nhất, không cần máy chủEach window has its own copy of the mod; a card folder is the simplest way, with no server
Phương án đã loạiRejected alternative
Đọc lại bản ghi phiên để tính lượng ngữ cảnh cả ngày: engine không đọc file lớn hơn 4 MiBRe-reading session transcripts for the day's total: the engine does not read files over 4 MiB

Hàm thuần tách khỏi phần vẽPure functions kept apart from drawing

Vì saoWhy
Phần tính test được nhanh, không cần dựng giao diện; phần vẽ có test riêng trên engine thậtThe computations test fast without building a UI; drawing has its own tests on the real engine
Phương án đã loạiRejected alternative
Chỉ xem ảnh chụp: đã có lần cả bảng trống mà test hàm thuần không bắt đượcScreenshots only: once the whole pane went blank and the pure-function tests could not catch it

4Cách kiểm chứngHow it is verified

  • 159 ca test chạy qua engine mod thật, gồm cả hàm thuần lẫn phần vẽ; kiểm kiểu báo 0 lỗi mới so với baseline.
  • Để chắc các test bắt được lỗi, 579 lỗi cài cố ý (510 vào hàm thuần, 69 vào phần vẽ) đều bị bắt; test nào không đỏ thì viết thêm ca.
  • Mỗi thay đổi giao diện được xem bằng ảnh chụp bảng thật trong VS Code, vì có lần cả bảng trống mà test hàm thuần không bắt được.
  • 159 tests run through the real mod engine, covering both pure functions and drawing; the type check reports 0 new errors against the baseline.
  • To make sure the tests catch real faults, 579 deliberate bugs (510 in pure functions, 69 in drawing) were all caught; any test that stays green gets a new case.
  • Every interface change is looked at in a screenshot of the real pane in VS Code, because once the whole pane went blank and the pure-function tests could not catch it.
